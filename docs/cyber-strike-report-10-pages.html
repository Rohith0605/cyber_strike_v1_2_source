01 / Project Overview

Abstract, Introduction & Objectives

Abstract

Cyber Strike is a browser-playable two-dimensional space shooter developed with Flutter and Dart. The player controls a spacecraft, automatically fires at approaching enemies, collects temporary weapon or shield upgrades, earns points, and advances through score-gated levels. The project combines custom canvas rendering with real-time state updates, keyboard and pointer input, collision detection, and a web deployment workflow.

Introduction

Arcade games bring together continuous simulation, event handling, visual feedback, and clear rules. Cyber Strike explores these ideas through a neon sci-fi setting and a compact single-player experience. Flutter widgets provide the application shell and HUD, while CustomPainter and Canvas draw the ship, enemies, projectiles, pickups, particles, stars, and other scene effects.

Dart manages the game state and update logic. Targeting the web makes the game shareable by URL without requiring visitors to install a native app.

Project objectives

  • Build a playable 2D arcade game with Flutter and Dart.
  • Render a dynamic space scene using custom drawing.
  • Manage movement, projectiles, collision, scoring, health, and level transitions.
  • Support keyboard and mouse/touch movement.
  • Provide power-ups, pause/resume, restart, and game-over states.
  • Publish the compiled web version through a repeatable hosting workflow.
Project scope

Cyber Strike is a single-player game. User accounts, online multiplayer, cloud saves, and remote leaderboards are not part of the documented implementation.

03 / Player Guide

Gameplay & Controls

Gameplay flow

  1. Start a run from the opening screen.
  2. Move the spacecraft around the playfield to avoid direct contact with enemy units.
  3. Allow automatic firing to engage enemies as they approach.
  4. Destroy enemies to collect points and progress through level thresholds.
  5. Move into falling pickups to collect weapon or shield upgrades.
  6. Pause or resume when needed; restart to begin a new run after game over.

Control reference

InputAction
W / Up ArrowMove upward.
A / Left ArrowMove left.
S / Down ArrowMove downward.
D / Right ArrowMove right.
P or EscPause or resume.

Enter or SpaceStart from menu or resume when paused.

Health and survival

The player starts with three health points. Health is intended to decrease only on direct enemy-to-ship collision, subject to the active shield or damage grace period. An enemy leaving the bottom of the playfield does not itself cause damage.

Keyboard focus

For browser keyboard input to work reliably, the game area needs focus. If controls do not respond, click within the game area and try again. Test keyboard and pointer input separately on the target browser before presenting the project.

Player tip

Keep moving, watch the HUD for level changes, and collect power-ups when it is safe to cross their path.

05 / Code Design

Architecture & Game Loop

High-level architecture

Application shell — CyberStrikeApp

Sets the MaterialApp, dark theme, colour scheme, and opens the game screen.

↓
Game controller — GameScreen / _GameScreenState

Owns the timer, player position, score, level, health, keyboard focus, active entities, and run-state flags.

↓
Entity models

Enemy, Bullet, Pickup, and Particle hold each object's state.

Input handlers

Keyboard and drag handlers translate user input into movement or state changes.

↓
Simulation & rendering

The update method advances state; GamePainter draws the resulting scene using Canvas.

Core components

ComponentResponsibility
EnemyPosition, kind, speed, radius, health, and lifecycle.
BulletProjectile position, velocity, radius, and cleanup.
PickupPickup kind, position, movement, and spin.
ParticlePosition, velocity, colour, and lifetime.
GamePainterPaints scene, entities, effects, and player ship.

Update loop

A periodic timer calls the game update method at intervals near 16 milliseconds. Each active tick applies movement, timers, enemy and pickup spawning, projectile and enemy movement, collision checks, scoring, cleanup, level updates, and the game-over condition. Rendering then reflects the current state.

A timer interval near 16 ms is not a guarantee of a steady 60 frames per second; browser throttling and device performance may affect the effective rate.

06 / Rules & Interface

Collision Logic & Visual Design

Collision detection

A bullet hits an enemy when the distance between their centres is less than the sum of their collision radii. The bullet is removed, enemy health is reduced, and the enemy is removed with its score award when health reaches zero.

distance(bullet, enemy) < bullet.radius + enemy.radius

Health and shield rule

Direct enemy-to-ship contact is the condition for player damage. If a shield is active, it absorbs the collision. Otherwise, a short damage cooldown prevents repeated rapid damage. Enemies that leave the bottom of the screen are cleaned up without reducing player health.

Game-over state

When health reaches zero, the running state stops and the game-over state is displayed. Restart resets the run-related state and clears active entities.

Visual design

Cyber Strike uses a dark navy space scene with bright cyan, magenta, violet, orange, and gold accents. Custom paths create the spacecraft and enemy silhouettes. Glowing bullets, star trails, gradient nebulae, perspective grid lines, particles, and brief screen shake provide motion and impact feedback.

Visual hierarchy

The HUD separates score, health, level, and notices from the active battlefield.

Object readability

Enemy colour, shape, and health bars distinguish threats; pickup symbols identify upgrades.

Feedback

Particle bursts show hits and defeats; status text announces upgrades and level changes.

Atmosphere

Background colour shifts and later-level asteroids give a sense of progression.

Verification considerations

Collision radii and visual overlap are approximations, so test edge cases with different window sizes. Confirm shield absorption, grace-period behavior, zero-health game over, and the no-damage rule for off-screen enemies.

Repository, Setup & Deployment

Repository structure

cyber_strike_v1_2_source/
├── .github/workflows/deploy.yml
├── lib/main.dart
├── web/index.html
├── pubspec.yaml
├── pubspec.lock
├── analysis_options.yaml
├── .gitignore
└── README.md

lib/main.dart contains the game implementation. web/index.html is the Flutter web entry template. pubspec.yaml defines metadata and packages. The workflow defines the cloud build and Pages deployment.

Run locally on Windows

Prerequisites: Flutter stable SDK in PATH, Git, a code editor, and Chrome.

  1. Open PowerShell and verify: flutter --version and flutter doctor.
  2. Clone the repository and enter it:
git clone https://github.com/Rohith0605/cyber_strike_v1_2_source.git
cd cyber_strike_v1_2_source
  1. Install packages and run the app:
flutter pub get
flutter run -d chrome

Build and publish

Flutter compiles the Dart project into static files for the browser. The release output is generated under build/web.

flutter build web --release --base-href "/cyber_strike_v1_2_source/"

The GitHub Actions workflow checks out the source, installs Flutter, gets dependencies, builds the web release, uploads build/web as a Pages artifact, then deploys it. In Settings → Pages, select GitHub Actions as the publishing source.

Known limitations

  • Game state is held in memory; refreshing starts a new session.
  • The current project does not document accounts, cloud saves, or online leaderboards.
  • Keyboard focus, touch behavior, and small-screen layout should be tested on target devices.
  • Timer cadence and rendering can vary with browser throttling or device performance.

Future enhancements

Possible improvements include audio controls, boss encounters, additional missions, saved high scores, stronger automated tests, responsive touch input, accessibility settings, and performance profiling.

Conclusion

Cyber Strike demonstrates how Flutter and Dart can support a browser-playable arcade game through custom 2D rendering, real-time state updates, input handling, collision rules, score-driven levels, and temporary power-ups. Reliable testing and release validation should precede larger gameplay expansions.
